# 第3回 解答

## 演習

- **第1回との比較**：第1回の素のLLMと同一条件での比較は未実施。今回の実験では、エージェントが用語集や講義要約をツールで取得し、回答に利用する動作を確認した。
- **ツール呼び出し**：比較実験の記録では、「LoRAとは何ですか？」に対して `search_glossary({"query": "LoRA"})`、「第3回の講義内容を教えて」に対して `get_lecture_summary({"lecture": 3})` が呼ばれた。CLIの `--trace` 出力そのものは取得していない。
- **LLM呼び出し回数**：LoRAの質問では両フレームワークとも2回。60試行の平均はPydantic AIが2.017回、Google ADKが2.067回だった。
- **追加したツール**：`make_quiz(lecture: int)` を実装した。docstringには、指定回の用語集から確認問題を作ることと、どのような質問で使うかを記載した。問題は講義番号から再現可能な形で選び、該当する回がない場合にも対応した。

## 宿題

**レベル：発展（a）／Google ADKへの移植と比較**

### 実装と評価方法

既存の `INSTRUCTIONS`、モデル設定、`search_glossary`・`get_lecture_summary`・`make_quiz` をそのまま利用し、Google ADK版を `adk_agent/glossary_agent/agent.py` に実装した。

ツールの登録方法は異なる。Pydantic AIでは `Agent(..., instructions=...)` に `agent.tool_plain(...)` で追加するが、ADKでは `Agent(..., instruction=..., tools=[...])` にまとめて渡す。

両フレームワークの回答とツール呼び出しを比較するため、記録用のスクリプトも作成した。質問は用語説明・2用語の比較・講義要約・未登録用語や誤前提の4カテゴリで、各5問。Gemini 3.5 Flash-Liteを使い、各質問をそれぞれ3回、計120試行（各フレームワーク60試行）実行した。記録項目は回答、ツール名と引数、LLM呼び出し回数、実行時間、トークン数とした。

### 結果（2026年11月9日）

| 指標 | Pydantic AI | Google ADK |
| --- | ---: | ---: |
| 正常記録 | 60/60 | 60/60 |
| 指定ツール使用率 | 60/60（100%） | 60/60（100%） |
| 平均ツール呼び出し回数 | 1.250 | 1.233 |
| 平均LLM呼び出し回数 | 2.017 | 2.067 |
| 平均処理時間 | 2.088秒 | 3.124秒 |
| 処理時間の中央値 | 2.012秒 | 2.207秒 |
| 入力トークン合計 | 72,969 | 82,422 |
| 出力トークン合計 | 11,878 | 11,188 |

指定したツールは両方とも全60試行で呼び出された。ただし、2用語の比較15試行で両方の用語を個別に検索したのは、Pydantic AIが15件、ADKが14件だった。ADKでは「LoRAとQLoRAの違いは？」の2回目にLoRAしか検索していなかったが、QLoRAについても回答していた。

### 考察

**ツールの呼び出しと回答の正確性は別に評価する必要がある。**

「宿題は『基礎・応用・発展』の3レベルですか？」という誤った前提を含む質問では、Pydantic AIが3/3件、ADKが2/3件で冒頭に「はい」と答えた。一方、本文には両者とも正しい「基礎・実装・発展」を列挙していた。用語集を参照していても、質問の前提を訂正できず、回答内で矛盾する場合があった。

架空の「OpenMCP認定資格」「ハイパーLoRA規約」「lec99-start」については、両者とも各3試行で用語集に記載がないと回答した。根拠のない定義を作る例は確認されなかった。ただし、用語集への未登録だけでは、その制度や用語自体が存在しないとは断定できない。

処理時間はPydantic AIの平均がADKより約33%短く、入力トークン数も約11.5%少なかった。ただし、ADKには21.388秒と16.902秒の遅い試行が含まれ、2つの方式は異なる時間帯に実行した。APIの混雑や初回実行の影響を切り分けられないため、フレームワーク自体の性能差とは判断できない。

今回、指定ツールの使用率は両者100%だった。それでも検索の網羅性や誤前提への対応には違いがあった。今後は、ツールを呼んだかだけでなく、必要な情報をすべて検索したか、取得結果と回答が整合しているかも評価する必要がある。

### 計測上の問題

初回実行では、Pydantic AIの計測コードで `result.usage()` を呼び出したため、回答の記録に失敗した。`result.usage` に修正し、初回のADK 60試行分を残したままPydantic AIの60試行を再実行した。初回の計測エラーはエージェントの失敗として集計していない。
