# 第3回発展課題：Pydantic AIとGoogle ADKの比較実験

## 目的・条件

第3回で扱った「モデル＋ループ＋ツール」のうち、エージェントのループを実装するフレームワークを変え、動作の違いを調べた。

Pydantic AIとGoogle ADKの両方で、`INSTRUCTIONS`、モデル設定（`AIE_MODEL`）、3つのPython関数（`search_glossary`、`get_lecture_summary`、`make_quiz`）を共有した。使用モデルは `gemini-3.5-flash-lite`。

用語説明・2用語の比較・講義要約・未登録用語や誤前提の4カテゴリから各5問、計20問を用意し、両フレームワークでそれぞれ3回実行した（合計120試行）。

`scripts/compare_agent_frameworks.py` で質問、回答、ツール名・引数、LLM呼び出し回数、処理時間、トークン数を記録した。各質問で使うべきツールは実験前に指定した。**指定ツール使用率は正答率とは別の指標**として扱う。

## 実行方法

リポジトリ直下で、環境変数 `GEMINI_API_KEY` を設定して実行する。

```bash
PYTHONPATH=. uv run --with 'google-adk>=2,<3' python -m scripts.compare_agent_frameworks
```

結果は `results/lec03_frameworks.json` に逐次保存する。動作確認のみの場合は `--limit 2 --repeats 1` を指定すると4試行になる。

### 計測コードの修正

初回の120試行ではADK側の60件を正常に記録できたが、Pydantic AI側はエージェント実行後の集計処理でエラーになった。原因は、`RunUsage` を取得する際に、プロパティである `result.usage` を `result.usage()` と呼び出していたことだった。

これはエージェントの回答失敗ではなく、計測コードの不具合である。修正後、ADKの60件を維持してPydantic AIのみを再測定した。

```bash
cp results/lec03_frameworks.json results/lec03_frameworks_before_fix.json
PYTHONPATH=. uv run --with 'google-adk>=2,<3' python -m scripts.compare_agent_frameworks --repair-pydantic
```

再測定したPydantic AIの60件はすべて正常に記録できた。最終結果にはADKの初回60件とPydantic AIの再測定60件を使用し、初回の計測エラー60件は評価に含めていない。

### ツール選択と回答内容

2用語比較の15試行で、両方の用語をそれぞれ検索したのはPydantic AIが15件、ADKが14件だった。ADKでは「LoRAとQLoRAの違いは？」の2回目にLoRAのみを検索したが、QLoRAについても回答した。

誤前提を含む「宿題は『基礎・応用・発展』の3レベルですか？」に対し、冒頭で誤って肯定したのはPydantic AIが3/3件、ADKが2/3件だった。どちらも本文では正しい「基礎・実装・発展」を列挙しており、回答内で矛盾が生じた。

「OpenMCP認定資格」「ハイパーLoRA規約」「lec99-start」の3つについては、両フレームワークとも用語集に登録がないと回答した。未登録という結果から、その概念自体が存在しないとまでは言えない。

## 考察と限界

- **検索と正答は別**：指定ツール使用率は両者100%だったが、2用語を個別に検索したか、誤った質問の前提を訂正できたかには差があった。回答全件の正答率は採点していない。
- **時間の比較には制約がある**：ADKには21.388秒と16.902秒の遅い試行があり、中央値の差は平均値ほど大きくない。さらに両方式の測定時間帯が異なるため、APIの混雑や初回実行の影響を分離できない。
- **条件が完全には一致しない**：同じモデル、指示、Python関数を使っても、プロンプトの構築やツール定義への変換、実行ループにはフレームワークごとの違いがある。観測した差をフレームワークだけの影響とは断定できない。
- **試行数が少ない**：各方式60試行の探索的な実験であり、一般的な優劣や統計的な有意差は主張しない。正答率やハルシネーション率を測るには、正解ラベルと採点基準を用意する必要がある。
