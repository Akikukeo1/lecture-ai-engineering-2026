# 第3回発展課題：Pydantic AI / Google ADK の比較実験

## 目的と条件

「モデル＋ループ＋ツール」のうち、ループを組み立てるフレームワークを変更した場合の挙動を観測する。両方式は同一の `INSTRUCTIONS`、モデル設定 `AIE_MODEL`、Python関数（`search_glossary`、`get_lecture_summary`、`make_quiz`）を使う。モデルは実験時に `gemini-3.5-flash-lite` を使用した。

質問を用語説明5問・2用語比較5問・講義要約5問・誤前提／未登録用語5問に分け、20問を各方式で3回ずつ実行した（合計120試行）。`scripts/compare_agent_frameworks.py` が質問・回答・ツール名と引数・モデル呼び出し回数・実行時間・トークン数をJSONに記録する。期待ツールは各質問について事前に設定し、**回答品質と区別して計数**する。

## 再現手順

リポジトリ直下で `GEMINI_API_KEY` を環境変数に設定し、次を実行する。

```bash
PYTHONPATH=. uv run --with 'google-adk>=2,<3' python -m scripts.compare_agent_frameworks
```

実測JSONは `results/lec03_frameworks.json` に逐次保存される。事前確認は `--limit 2 --repeats 1` で4試行。

### 初回の計測不具合と修復

初回の120試行はADK側60件の記録に成功したが、Pydantic AI側60件はエージェント実行後に `result.usage()` で `TypeError: 'RunUsage' object is not callable` が発生し、結果を記録できなかった。これは**フレームワークのタスク失敗ではなく、測定処理のバグ**。修正後に以下のコマンドでADKの実測60件を保持し、Pydantic AIだけ再計測した。

```bash
cp results/lec03_frameworks.json results/lec03_frameworks_before_fix.json
PYTHONPATH=. uv run --with 'google-adk>=2,<3' python -m scripts.compare_agent_frameworks --repair-pydantic
```

2回目は60件すべて正常記録でき、最終JSONには両方式60件ずつの計120件が含まれる。初回のPydantic計測エラー60件は成功率等の分母に含めず、修復後の実測のみを比較した。

## 結果（2026-11-09）

| 指標 | Pydantic AI (n=60) | Google ADK (n=60) |
| --- | ---: | ---: |
| 正常終了 | 60 | 60 |
| 指定ツール使用率 | 100% | 100% |
| 平均ツール呼び出し | 1.250 | 1.233 |
| 平均モデル呼び出し | 2.017 | 2.067 |
| 平均時間 | 2.088秒 | 3.124秒 |
| 中央時間 | 2.012秒 | 2.207秒 |
| 入力トークン | 72,969 | 82,422 |
| 出力トークン | 11,878 | 11,188 |

2用語比較の15試行では、両方の用語を別々に検索した割合がPydantic AI 15/15、ADK 14/15だった。ADKの「LoRAとQLoRAの違いは？」の2回目は、LoRAのみを検索したものの、QLoRAを含む回答は生成した。この1例から検索の網羅性の違いが確認できる。

誤前提「宿題は『基礎・応用・発展』の3レベルですか？」への冒頭の誤肯定はPydantic AI 3/3、ADK 2/3。回答後半は両者とも「基礎・実装・発展」と正しく列挙しており、出典へのアクセスと回答の整合性は別問題だった。「OpenMCP認定資格」「ハイパーLoRA規約」「lec99-start」では両方式とも用語集に未登録と説明した。

## 解釈・限界

- **期待ツール使用率 ≠ 正答率**。ここでは回答全件の自動正誤判定はしていない。誤前提の訂正、2語それぞれの根拠検索、情報がない場合の保留は別指標として分析した。
- ADKの初回試行に21.388秒と16.902秒の遅い例が含まれる。中央値での差は平均値より小さい。さらにADKとPydantic AIは異なる時間帯で測定したため、API混雑やウォームアップの影響を分離できない。
- 同じモデル・指示・関数を用いても、フレームワーク固有のプロンプト構築、関数宣言の変換、イベントの扱いが完全一致するとは限らない。差をフレームワークのみに因果帰属できない。
- 20問×3回の小規模で探索的な比較であり、統計的に一般化した優劣や「有意差」は主張しない。正答率やハルシネーション率の全面的な測定には、別途正解ラベル／採点基準が必要となる。
