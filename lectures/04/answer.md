## 宿題

- **取り組んだレベル：実装**
- **やったこと**：
  - `data/eval/my_cases.jsonl` に独自の質問・期待するふるまいを10件設計し、第3回エージェント（講義資料RAG）で実際に回答を生成した。
  - 通常系・言い換え・誤前提・未掲載の情報・宿題の完成解答要求・範囲外・指示上書き・講義横断を評価した。
  - 10件を人手で採点し、Gemini 3.5 Flash-Lite（`gemini-3.5-flash-lite`）による4つの意味基準の採点と、コードによる「回の表示」判定を比較した。モデルの判定理由も保存した。
  - `scripts/lec04_report.py` で基準別一致率、判定可能率、不合格再現率、見逃し・過検出を集計する仕組みを用意した。
  - 「回の表示」はコードによる構文検査、それ以外の根拠・範囲・ヒント・分かりやすさはLLMと人の判定を用いた。単なる一致率だけで採点器の品質を評価しないよう、判定可能率と混同行列の内訳も確認した。
- **実測結果**（保存先：`lectures/04/my_report.md`、実行日：2026-11-16）：
  - **基準別一致率**：根拠 **10/10**、範囲 **9/10**、ヒント **9/10**、分かりやすさ **10/10**、回の表示 **3/10**。
  - **要確認（LLMのunsure）**：0件。**自動判定可能率**：10/10。**総合判定の一致率**：3/10。
  - **不一致9項目**：回の表示7項目、範囲1項目（#08）、ヒント1項目（#06）。これらは実測した人手ラベルとの不一致であり、直ちに採点器の誤りを示すものではない。
  - **追加検査が必要な点**：#06は「第3回で満点だった受講者数」を尋ねる質問で、宿題の完成解答要求ではないにもかかわらず人手で`hint=fail`とラベル付けした。#08は天気を尋ねられて資料に情報がないと回答しており、講座の範囲外として回答を断ったことを`scope=pass`と評価するのが基準上は自然である。この2件のラベルは**未修正**で、再確認が必要。
  - 「回の表示」については、回答本文に出典があることと、**最終行に「第N回」という字句があること**は別の要件であり、人とコードで解釈がずれていた。
- **気づき・疑問**：
  - 今回の実験は「採点器の信頼性」の検証であって、エージェントの正答率そのものではない。意味基準で高一致率でも、そもそも人が明確に不合格とした実例が乏しく、不合格検出性能を十分に確認できない。
  - 人がラベルを付ける際にも基準の解釈が揺れる。判定の不一致はLLMだけの誤りとせず、ルーブリックの曖昧さ、コード検査の仕様、ラベル付けの誤りを分けて分析する必要がある。
  - `unsure`を一致率の分母から除外する仕組みでは、coverageを併記しないと実態を誤認する。今回は全件判定したが、これは正確性を保証しない。
  - `app.agent` は講義資料RAGを用いる一方、第4回の`rubric.md`は用語集に基づく「根拠」の基準であり、資料への忠実性の評価としては構成概念が一致していない。形式上の出典表記があっても引用の正確性は保証されない。
  - 10件・単独ラベラーの小規模評価なので、割合の一般化やモデル間の優劣推定は行わない。今後は曖昧な項目の定義を先に固定し、不合格事例も十分に含むデータセットで追試する必要がある。


> **公開用データの注記**：評価ケース#08の地名は、実験後に公開用として「東京」に置換した。生成済みの回答・人手ラベル・LLM採点結果は変更していない。このため、公開版の質問文と実際にモデルへ送信した質問文は地名のみ異なる。厳密な再現実験では公開版で再実行する必要がある。

### 実測・再現手順

```bash
# リポジトリのルートで実行する。GEMINI_API_KEY は環境変数から読み込む。
uv sync --frozen
uv run pytest -q
uv run --env-file .env python -m app.judge --generate --cases data/eval/my_cases.jsonl --wait 15
uv run --with streamlit==1.66.1 streamlit run tools/annotate.py
# Streamlit の「ラベル付け」で対象 data/eval/my_cases.jsonl と
# 保存先 lectures/04/my_labels.jsonl を選択し、全10件の人手判定を保存する。
# Streamlit 停止後:
uv run --env-file .env python -m app.judge --cases data/eval/my_cases.jsonl --labels lectures/04/my_labels.jsonl --out lectures/04/my_judge_result.json --wait 15
uv run python -m scripts.lec04_report --cases data/eval/my_cases.jsonl --labels lectures/04/my_labels.jsonl --judge lectures/04/my_judge_result.json --out lectures/04/my_report.md
```

**注**：上記コマンドは実行手順であり、実行済みという意味ではない。`.env` はローカルの秘密情報でGitに追加しない。`--generate` は各問成功直後にケースファイルを更新し、429などで止まっても再実行時に未回答だけ処理する。`--wait 15` は呼び出し間隔を空ける指定であり、日次クォータ超過を解決するものではない。第三者の確認が必要な項目や実験結果は、実測前に記入しない。
